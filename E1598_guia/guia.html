Capítulo 1

¿Qué construiremos?

Un asistente que contesta en Telegram las preguntas frecuentes de un restaurante, usando IA y sin escribir código.

El problema empresarial

Un restaurante recibe a diario las mismas preguntas: ¿cuánto cuesta?, ¿qué hay en el menú?, ¿a qué hora abren?, ¿tienen servicio a domicilio? Si una persona contesta cada mensaje manualmente, se pierden ventas en horas pico, las respuestas son desiguales y el equipo deja de atender a quienes ya están en el local.

Responder manualmenteCon esta automatización (demo)
Alguien debe estar mirando el teléfono.El flujo responde en segundos, a cualquier hora en que n8n esté activo.
Cada empleado contesta distinto.El tono y la información salen de un único system prompt.
Información dispersa (memoria, notas).Los datos autorizados están escritos en un solo lugar.
Riesgo de prometer algo incorrecto.El asistente tiene la regla explícita de no inventar lo que no sabe.

El resultado que conseguirás

EtapaNodoQué hace
1Telegram TriggerDetecta el mensaje que un cliente envía al bot.
2Edit FieldsOrganiza los datos: nombre, chat, mensaje, fecha, canal.
3AI Agent + OpenRouter Chat ModelCon un system prompt, el modelo redacta la respuesta.
4Edit Fields (segundo)Prepara la respuesta y recupera el Chat ID correcto.

Esto es una demostración

Es un primer prototipo didáctico. Todavía no guarda historial, no registra clientes, no deriva a una persona y usa datos ficticios. En el Capítulo 16 verás qué falta para un sistema empresarial.

Objetivos de aprendizaje

Al terminar, podrás:

  1. Crear un bot de Telegram con BotFather y proteger su token.
  2. Guardar credenciales en n8n y usarlas en nodos.
  3. Leer un JSON y escribir expresiones {{ }} que extraen datos.
  4. Configurar un AI Agent con OpenRouter y un system prompt que no invente información.
  5. Responder dinámicamente al chat correcto y probar el flujo con tres casos.

Los datos reales de Telegram: cajas dentro de cajas

Telegram no entrega una ficha plana: entrega una caja message que contiene otras cajas (from = quién escribió, chat = la conversación) y valores como text o date.

Las expresiones de n8n

Una expresión es una “instrucción para ir a buscar un dato”. En vez de escribir un valor fijo, le dices a n8n en qué casilla de la caja está.

Expresión típica
{{ $json.message.text }}
ParteQué hace
{{ y }}Abren y cierran la expresión. Todo lo de adentro se calcula; lo de afuera es texto normal.
$jsonLos datos que llegan al nodo actual desde el nodo anterior conectado.
.messageEntra a la caja message.
.textToma el valor de la casilla text: el mensaje del cliente.

Corrección: la expresión del chat de clase estaba mal formada Corrección técnica

En el chat (≈ min. 36) se escribió {{$json.message.text {{. Cierra con {{ en lugar de }}, por lo que n8n no la puede evaluar. La forma correcta es:

{{ $json.message.text }}

Los espacios interiores son opcionales; las llaves de cierre, no.

Cómo comprobar que una expresión funciona

  1. Ejecuta antes el nodo anterior (para que haya datos de prueba).
  2. En el campo, cambia de Fixed a Expression (interruptor arriba a la derecha del campo, o escribe {{ al inicio).
  3. Pega la expresión. Debajo aparece una vista previa del resultado.
  4. Si la vista previa muestra el texto esperado, funciona. Si dice undefined o [null], la ruta no existe: revisa mayúsculas, puntos y nombres.
  5. Alternativa sin escribir: arrastra la casilla desde el panel INPUT (izquierda) hasta el campo; n8n escribe la expresión por ti.

Por qué no conviene dejar fijo el Chat ID Corrección técnica

Si pegas tu propio ID en el nodo, el bot siempre te contestará a ti, aunque le escriba otro cliente. @userinfobot es un bot de terceros, útil solo como herramienta auxiliar de diagnóstico en un chat privado (p. ej., para comparar que el ID que llega a n8n es el tuyo).
