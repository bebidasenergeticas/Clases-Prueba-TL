Qué decide el agente y qué resuelve una regla

Prueba rápida: ¿la misma entrada debe producir siempre la misma salida? Si la respuesta es sí, probablemente es una regla.

Juicio probabilístico · agente

Conviene al agente

Cuando la entrada es ambigua o está en lenguaje natural.

  • Interpretar el mensaje libre de un cliente
  • Extraer datos de un texto sin estructura
  • Clasificar intención, urgencia y tono
  • Redactar una respuesta personalizada
  • Elegir qué herramienta usar en cada caso
Lógica determinista · workflow

Conviene a una regla

Cuando la lógica puede escribirse y debe repetirse igual.

  • Validar el formato de correo y teléfono
  • Calcular un precio con la tabla vigente
  • Enrutar según monto, región o categoría
  • Registrar o actualizar datos en el CRM
  • Reintentar y alertar ante un error

¿Cinco agentes para lo que resuelve un nodo IF? Más complejidad y más fallos, sin beneficio.

MCP: un contrato común entre la IA y las herramientas

Sin un estándar

N × M  cada combinación, una integración a la medida

Con MCP

N + M  cada parte implementa el protocolo una vez

Protocolo abierto que estandariza cómo las aplicaciones de IA se conectan con fuentes de datos y herramientas externas.

Su función real: acordar cómo se descubren capacidades, cómo se invocan y cómo regresan los resultados. No es un modelo, ni un agente, ni una plataforma de automatización.

Arquitectura MCP: host, cliente y servidor

Host

La aplicación de IA

Coordina al modelo y crea un cliente por cada servidor al que se conecta.

Cliente

Una conexión dedicada

Vive dentro del host y mantiene una relación 1:1 con un único servidor.

Servidor

Quien ofrece capacidades

Programa local o remoto que expone tools, resources y prompts.

Tres capacidades que un servidor puede ofrecer

Tools

Acciones que el modelo puede invocar para hacer algo en otro sistema.

Quién decide usarla
El modelo, según la petición
Ejemplo
registrar_oportunidad(cliente, producto, cantidad)
Métodos
tools/list · tools/call

Resources

Datos que aportan contexto: documentos, registros o archivos para consultar.

Quién decide usarlo
La aplicación, al preparar el contexto
Ejemplo
Catálogo de productos y política de precios vigente
Métodos
resources/list · resources/read

Prompts

Plantillas reutilizables que estructuran una interacción frecuente.

Quién decide usarlo
La persona usuaria, al elegirlo
Ejemplo
“Preparar cotización formal para cliente corporativo”
Métodos
prompts/list · prompts/get

Analogía: tools son verbos, resources son documentos de consulta y prompts son formularios guiados. En sentido inverso, el cliente también ofrece primitivas al servidor: sampling, elicitation y logging.

Una llamada MCP, paso a paso

1

Descubrimiento

El cliente pide la lista de herramientas: nombre, descripción y esquema de entrada.

2

Selección

El modelo compara la petición con las descripciones y elige una herramienta.

3

Argumentos

El modelo genera los parámetros con el formato que exige el esquema.

4

Ejecución

El cliente envía la llamada; el servidor actúa sobre el sistema real.

5

Respuesta

El resultado regresa al modelo como contexto para continuar o responder.

Antes del paso 4, el host puede pedir confirmación a la persona usuaria.

API, webhook, conector y MCP: cuatro formas de conectar

API

Una ventanilla: preguntas y te responden.

Quién inicia
El consumidor, cuando lo necesita.
Pensada para
Programas que conocen el contrato de antemano.
Ejemplo
Consultar los datos de un contacto en el CRM.

Webhook

Un timbre: te avisan cuando algo ocurre.

Quién inicia
El sistema de origen, al ocurrir el evento.
Pensado para
Reaccionar a eventos sin consultar repetidamente.
Ejemplo
El formulario avisa a n8n de una nueva solicitud.

Conector

Un adaptador listo para una plataforma concreta.

Quién inicia
La plataforma que lo usa, según la operación.
Pensado para
Usar un servicio sin programar su API.
Ejemplo
El nodo de Google Sheets dentro de n8n.

MCP

Un idioma común entre la IA y las herramientas.

Quién inicia
El cliente MCP, a partir de la decisión del modelo.
Pensado para
Aplicaciones de IA que descubren capacidades al momento.
Ejemplo
Un agente encuentra y ejecuta un workflow de n8n.

No compiten: se combinan. Un servidor MCP suele llamar APIs; un conector encapsula una API; un webhook inicia un flujo.

Lo que MCP no hace

Estandarizar la conexión no equivale a resolver la seguridad ni el diseño del proceso.

01

No elimina la autenticación.

El servidor sigue necesitando credenciales para llegar a cada sistema, y una conexión remota también debe autenticarse, por ejemplo con OAuth o tokens.

02

No reemplaza universalmente a las APIs.

Muchos servidores MCP traducen llamadas a APIs existentes. Para integraciones fijas entre sistemas, una API o un conector siguen siendo la vía directa.

03

No garantiza permisos adecuados.

Una herramienta puede hacer todo lo que permita su credencial. El alcance lo definen quienes configuran servidores, cuentas y roles.

04

No vuelve confiable lo que conecta.

Descripciones y resultados de herramientas son información externa: pueden contener errores o instrucciones maliciosas. Se validan antes de actuar.

n8n: el motor que ejecuta procesos

Plataforma de automatización de flujos de trabajo que combina integraciones, lógica y componentes de IA. Puede usarse en la nube o instalarse en infraestructura propia.

Trigger

Evento que inicia la ejecución: formulario, correo, horario o webhook.

Nodo

Un paso con una tarea concreta: transformar, decidir, consultar o enviar.

Credencial

Autorización guardada para conectarse a un servicio, separada de la lógica.

Ejecución

Registro de cada corrida: datos de entrada, salida y errores por nodo.

Workflow de error

Flujo que se activa cuando otro falla, para alertar o compensar.

Dos formas de exponer n8n por MCP

Nivel instancia

MCP de instancia

Qué es
Un servidor MCP integrado en la instancia de n8n.
Qué expone
Los workflows que se habilitan explícitamente para MCP.
Configuración
Se activa en la instancia y se habilita workflow por workflow.
Autenticación
OAuth o token de acceso.
Uso típico
Dar a un asistente acceso controlado a procesos que ya existen.
Nivel workflow

Nodo MCP Server Trigger

Qué es
Un nodo disparador que convierte un workflow en servidor MCP.
Qué expone
Solo las herramientas conectadas a ese nodo.
Configuración
Dentro del workflow; ofrece una URL de prueba y otra de producción.
Autenticación
Configurable en el nodo, por ejemplo bearer o encabezado.
Uso típico
Diseñar un servidor MCP a medida con un conjunto acotado de herramientas.

Dirección inversaEl nodo MCP Client Tool permite que un agente dentro de n8n use herramientas de un servidor MCP externo.

Caso conductor · arquitectura conceptual

La misma empresa de dulces, ahora conectada

La empresa de la clase anterior ya tiene su equipo de marketing. Ahora recibe solicitudes de cotización por formulario web y mensajería, y necesita convertirlas en operaciones.

Lo que hoy se complica
  • Solicitudes incompletas que obligan a preguntar de nuevo
  • Respuestas que dependen de quién revisa la bandeja
  • Datos dispersos entre correos y hojas de cálculo
  • Seguimiento que depende de la memoria de cada vendedor

Objetivo: responder con rapidez y consistencia, registrar cada oportunidad y no perder el seguimiento.

Confianza por diseño: los controles

01

Supervisión humana

Aprobación antes de enviar cotizaciones, aplicar descuentos o contactar a clientes clave.

02

Permisos mínimos

Cada credencial con el alcance justo: quien consulta el catálogo no puede borrar contactos.

03

Manejo de errores

Reintentos acotados, workflow de error y escalamiento a una persona.

04

Seguridad

Credenciales fuera de los prompts, entradas validadas y desconfianza ante instrucciones dentro de mensajes externos.

05

Trazabilidad

Un ID por solicitud enlaza ejecuciones, decisiones del agente, aprobaciones y cambios en el CRM.

Penúltima sesión · una reflexión

Las herramientas cambiarán de nombre cada año. Lo que permanece es el criterio: saber qué automatizar, qué delegar a un agente y qué decisión conservar como humana.

La IA no reemplaza el juicio profesional; lo amplifica. Quien entiende el proceso, los datos y las personas detrás de cada flujo es quien convierte la tecnología en valor.

Un agente inteligente no es un sistema empresarial.Las conexiones, los procesos y los controles lo convierten en uno.
