Práctica 3 · Landing page DENTEA

Una landing page odontológica premium construida por todos con el mismo prompt, para comparar OpenCode con plataformas como Lovable.

Realizado en clasePrompt original P06

8.1 Contexto

En una clase anterior el grupo había creado una landing de dentistas con Lovable. Esta vez el profesor propuso repetirla con OpenCode «para comparar qué tan mal o bueno puede ser para una landing page», y después que cada quien hiciera la suya (capítulos 9–10) y la publicara (capítulo 14). DENTEA es un nombre de ejercicio: una clínica ficticia.

8.2 Prompt original completo

P06 Prompt original · chat 01:39:17 · ProfesorDestino: OpenCode · texto literal
Aviso dado en clase (≈ 1:40)«El prompt les va a pedir iniciar sesión en Google Flow. Si pueden, pongan su contraseña; si no, díganle que esa parte de las imágenes no la haga.» Se sugirió usar una cuenta alterna. Recomendación de esta guía: la contraseña se escribe solo en la página oficial de Google, nunca en el chat del agente.

8.4 Prompts mejorados

Prompt mejorado Las versiones del subagente (sencilla y avanzada) están en los Anexos B1 y B2, sección P06. La avanzada añade: arquitectura (HTML/CSS/JS estático o React+Vite), accesibilidad (contraste, teclado, alt), rendimiento (imágenes optimizadas, carga diferida), control de dependencias, SEO básico (título, descripción, Open Graph), enlace wa.me con número provisional, testimonios marcados como ficticios, pruebas visuales y preparación para GitHub Pages.

8.5 Tutorial de construcción

  1. Usa tu carpeta de clase o crea una subcarpeta dentea (recomendado: un proyecto por carpeta facilita publicarlo después).
  2. Abre OpenCode y elige el modelo.
  3. Abre una sesión nueva y pega el prompt (original o V1).
  4. Opcional: cambia primero a plan y pide «explícame tu plan antes de construir».
  5. Revisa las solicitudes de acceso: navegador, Google Flow, instalación de paquetes (npm install).
  6. Autoriza solo lo legítimo; si no quieres usar Flow: «omite Google Flow y usa marcadores de imagen».
  7. Espera: con modelos gratuitos tarda (en clase varios estudiantes seguían esperando a los 15–30 min).
  8. Abre el proyecto en el navegador integrado o pide la dirección local (p. ej. http://localhost:5173).
  9. Prueba la navegación: cada enlace del menú debe llevar a su sección.
  10. Prueba los botones: «Agendar por WhatsApp» debe abrir wa.me/… con el mensaje prellenado.
  11. Revisa en computadora.
  12. Revisa en móvil: pide «muéstrala en tamaño de celular» o reduce la ventana.
  13. Anota los errores (texto encimado, imágenes rotas, animaciones bruscas).
  14. Solicita una mejora agrupada.
  15. Cuando esté lista, pasa al capítulo 14 para publicarla.
Si la página ya se ve pero el agente «sigue trabajando»Pasó en clase. La página ya existe en tu carpeta; el agente puede estar optimizando o corrigiendo. Puedes abrir otra sesión con + para el siguiente paso; no pierdes lo hecho (ver incidencia B y K, capítulo 15).
