13.1 Qué estábamos intentando conseguir

Conectar OpenCode con la cuenta de GitHub de cada estudiante para que, a partir de ese momento, bastara una frase («crea un repositorio y publícalo») para publicar cualquier proyecto. Para eso la computadora necesita:

Git

Guarda el historial y sube los archivos.

GitHub CLI (gh)

Programa oficial de GitHub para la terminal: inicia sesión, crea repositorios, configura Pages.

Una sesión autorizada

Tu cuenta autoriza a gh desde el navegador; el agente nunca ve tu contraseña.

Explicado en clase Orden indicado: 1) iniciar sesión en github.com en el navegador normal; 2) pegar el prompt en una sesión de OpenCode (nueva o la misma); 3) esperar a que el agente instale y pida la autorización. El profesor no lo hizo en su pantalla porque ya tenía todo instalado.

13.6 Auditoría: por qué P11 corregía a P09

Fallos de P09 en la práctica

  • No instalaba Git si faltaba.
  • El código de dispositivo quedaba oculto en una terminal no interactiva.
  • Sin instrucción para códigos caducados.
  • Sin refresco del PATH tras instalar.
  • Sin pasos para crear el repositorio: el agente improvisaba (Netlify).

Lo que añadió P11

  • Git + gh con aceptación de acuerdos.
  • Ventana visible y página de dispositivo abierta automáticamente.
  • --clipboard (existe: «Copy one-time OAuth device code to clipboard»).
  • Verificación de identidad (gh api user --jq .login).
  • Revisión de secretos y .gitignore.

Pendientes que ni P11 resuelve y que corrigen las versiones del subagente (Anexos B1/B2, secciones P09–P11): pedir explícitamente un código nuevo si caduca; separar «instalar y autenticar» de «publicar»; configurar git config user.name/user.email sin inventar datos (usar los de la cuenta o preguntar); decidir público/privado según si se usará Pages; y una prueba final que no dependa de la palabra del agente.

13.8 Flujo correcto de autenticación

  1. OpenCode inicia el proceso (con el prompt V1 del Anexo B1).
  2. GitHub CLI genera un código temporal; el agente debe mostrártelo en el chat.
  3. Se abre (o abres tú) https://github.com/login/device. Comprueba el dominio exacto.
  4. Si te lo pide, inicia sesión en la página oficial.
  5. Escribe o pega el código y pulsa Continue.
  6. Lee los permisos que solicita «GitHub CLI» y pulsa Authorize (botón verde) si estás de acuerdo.
  7. GitHub confirma que el dispositivo está conectado.
  8. Vuelve a OpenCode y escribe «ya autoricé, continúa y verifica».
  9. El agente ejecuta gh auth status.
  10. Y confirma la identidad con gh api user --jq .login: debe ser tu usuario.
Así se resolvió en clase (pantalla compartida, ≈ 2:57–3:00)La estudiante tenía abierta una ventana «Windows PowerShell 5.1 · Autorización de GitHub CLI» y el navegador pidiendo iniciar sesión otra vez. El profesor le indicó: minimizar PowerShell; si no aparece la página, copiar la URL https que muestra PowerShell (clic derecho o Ctrl+C) y abrirla en Chrome; usar el código que aparecía en la PowerShell; Continue → Authorize en verde. Conclusión dicha en voz alta: «El código no llega por correo».

13.9 Seguridad: ventanas de permisos de Windows

Una estudiante vio una ventana que pedía permiso para «hacer cambios en tu equipo» con el nombre de una persona que no conocía, y la rechazó. El profesor: «estuvo bien… hay que tener cuidado cuando no conocemos el nombre». Lo esperable es ver como editor algo relacionado con lo que se instala (GitHub, Git, Microsoft para winget, OpenCode).

Cómo revisar una ventana de Control de cuentas de usuario

  1. Lee el nombre del programa. ¿Coincide con lo que pediste instalar?
  2. Mira el «Editor comprobado». Si dice «Desconocido» o un nombre ajeno, desconfía.
  3. Mostrar más detalles: revisa la ruta del archivo (¿viene de Descargas? ¿de una carpeta temporal rara?).
  4. Relaciona con la operación: ¿el agente acaba de decir que iba a instalar algo?
  5. Si dudas, rechaza. Pregunta al agente: «¿qué programa intentaste ejecutar y desde qué ruta?».
  6. Consulta la documentación oficial del programa.
Nunca
  • Autorices automáticamente cualquier ventana para «avanzar».
  • Desactives el antivirus, SmartScreen o el Control de cuentas.
  • Ejecutes scripts que te pase alguien sin saber qué hacen.
Matiz sobre una indicación de claseAnte otra ventana, se recomendó pulsar «select» para ver qué pasaba. Es razonable solo si la ventana corresponde claramente a la operación en curso (p. ej. PowerShell de GitHub CLI). Aplica primero la lista de la izquierda.
Sobre la terminal«Si les aparece la terminal, no se me espanten, no es nada malo»: PowerShell solo es otra forma de dar órdenes a la computadora. Lo que importa es qué comando se ejecuta.
