Cómo dos agentes pueden colaborar sobre el mismo proyecto, qué se demostró en clase y cómo hacerlo sin que se pisen.

7.1 La pregunta que originó la demostración

Chat 01:03:26 · una estudiante«¿Tenemos forma de ligar OpenCode con un proyecto que tengamos en Claude para que pueda acceder automáticamente a todo el contexto?»

Explicado en clase El profesor dio dos formas, y una tercera surgió de otra estudiante:

FormaCómo funcionaObservaciones
1. Carpeta compartidaAmbos agentes abren la misma carpeta local. Cada uno lee lo que el otro escribió.«La más fácil». Funciona en la misma computadora.
2. Repositorio compartidoEl proyecto se sube a GitHub; cada agente se conecta al repositorio, trae los cambios y sube los suyos.Funciona entre computadoras y en la nube. Requiere saber commit/push (cap. 12).
3. Varios modelos en un arnés (aportada por una estudiante)OpenCode permite añadir proveedores (Google, OpenAI, Anthropic y más de 70) y usar sus modelos dentro de la misma app.Es orquestación de modelos, no de agentes. Se paga cada uso de API: riesgo de costos.
Precisión técnicaCompartir una carpeta no crea un protocolo de comunicación entre agentes. Se «comunican» indirectamente: uno deja archivos (notas, reportes, código) y el otro los lee porque se lo indicas. El profesor relató que, poniendo a Codex como «ayudante» de Claude Code, Codex dejaba archivos del tipo «tu código en esta parte no está correcto, revísalo», y Claude Code los leía y corregía. Es colaboración por archivos, coordinada por ti.

7.3 La demostración, paso a paso

Demostración del profesor «No es práctica, no todos tenemos Claude Code.» Instrucciones orales reconstruidas (no hay texto en el chat):

  1. Abrir el mismo proyecto. En la app de Claude Code: nuevo entorno local → agregar carpeta → elegir otra carpeta → Documentos → clase E1601.2. El profesor comprobó que era la misma carpeta por su fecha de creación. (Comentó que la forma de agregar proyectos «había cambiado un poquito».)
  2. Elegir modelo y esfuerzo. Sonnet con esfuerzo medio, que luego subió «un poquito más alto para que no se vaya a equivocar».
  3. Dar contexto (P04, oral). «Conéctate a la calculadora que hizo OpenCode en este proyecto y, sobre todo, conéctate al repositorio de GitHub [enlace]».
  4. Asignar la mejora (P05, oral). «Mejora la calculadora, hazla más intuitiva y fácil, mejora el diseño y, por ejemplo, agrega animaciones 3D». El profesor admitió que «haría falta un mejor prompt».
  5. Dar a OpenCode un papel de apoyo. «Claude Code [está trabajando] sobre el proyecto, sobre el repositorio. Ayúdale y deja el camino abierto para que Claude Code pueda trabajar mejor». Para que OpenCode «supiera» qué hacía Claude Code, el profesor le envió capturas de pantalla.
  6. Lanzar subagentes. «Lanza subagentes de Sonnet [5.5, esfuerzo medio] para entender todos los procesos industriales, corporativos, de trabajos en el sector privado y público o emprendimientos que se pueden automatizar o delegar a agentes con IA, para agregarlos [a la calculadora]» y «lanza otro subagente de Sonnet para mejorar la interfaz».
  7. Esperar e integrar. Claude Code respondió que esperaría a los subagentes, integraría el catálogo «al backend de la calculadora», probaría todo y avisaría; «hasta entonces no toco el HTML para evitar conflictos». OpenCode, mientras, subió algunos archivos al repositorio.
  8. Resultado. Tras el descanso: catálogo «generado, validado: 327 procesos con 327 IDs únicos», con conteo por sector (industria y manufactura, logística, recursos humanos, legal y compliance…). Claude Code probó la interfaz en el navegador; el profesor canceló el segundo subagente para ver el resultado. Los cambios aparecieron en el enlace público.
Cómo interpretar «327 procesos»Es un resultado reportado por el agente durante la demostración. Que los 327 IDs sean únicos solo indica que no hay duplicados de identificador, no que los procesos estén validados por expertos ni que sus porcentajes de automatización sean correctos. Trátalo como un borrador útil que habría que revisar.

7.4 ¿Qué es un subagente y por qué ahorra tokens?

Un subagente recibe una tarea acotada y su propio contexto. El profesor destacó que Claude Code redactó solo un buen prompt para el subagente («Eres investigador de automatización con IA. El objetivo es construir un catálogo amplio y realista…»). Ventajas: el agente principal no llena su conversación con toda la investigación (ahorra tokens), las tareas corren en paralelo y cada subagente es más específico. Riesgos: resultados de calidad variable y cambios simultáneos sobre los mismos archivos.

7.5 Repositorio compartido: conceptos mínimos

RepositorioCarpeta del proyecto con historial de cambios, alojada (también) en GitHub.
Commit«Foto» guardada de los cambios con un mensaje descriptivo.
PushSubir tus commits al repositorio remoto.
PullTraer los cambios que otro (o el otro agente) subió.
Rama (branch)Línea de trabajo paralela; main es la principal.
ConflictoDos cambios distintos sobre las mismas líneas: hay que decidir cuál queda.

Problema de concurrencia

Si OpenCode y Claude Code editan index.html al mismo tiempo, uno puede sobrescribir el trabajo del otro o generar un conflicto. Claude Code lo evitó esperando. Hazlo explícito en tus instrucciones.

7.6 Método recomendado para que no se pisen

Adaptación pedagógica

  1. Responsabilidades claras: «OpenCode solo instala dependencias y ejecuta pruebas; Claude Code modifica la interfaz».
  2. Nunca el mismo archivo a la vez: indica qué archivos puede tocar cada uno.
  3. Ramas separadas cuando uses repositorio: mejora-diseno para uno, catalogo para otro.
  4. Integración controlada: uno solo une los cambios (merge) y tú lo apruebas.
  5. Pruebas después de integrar: abrir la app, probar campos, revisar móvil.
  6. Respaldo: commit antes de cada cambio grande; así puedes volver atrás.
  7. Un archivo de coordinación (p. ej. NOTAS_AGENTES.md) donde cada agente anota qué hizo y qué falta.
P05·V1 Segunda fase: mejorar sin romperPara Claude Code u OpenCode · Prompt mejorado
Trabaja sobre la calculadora de automatización que ya existe en esta carpeta.
1. Primero inspecciona: lista los archivos, ábrela en el navegador y descríbeme en 5 viñetas qué funciona y qué falla. No modifiques nada todavía.
2. Propón un plan de mejora (diseño más intuitivo, selector de procesos por sector, animaciones sutiles, informe imprimible). Espera mi "OK".
3. Al aplicar cambios: no reescribas desde cero lo que ya funciona, no cambies las fórmulas sin mostrarme antes/después, y si otro agente está trabajando en la carpeta, no edites el mismo archivo que él; anota tus cambios en NOTAS_AGENTES.md.
4. Al terminar: prueba en escritorio y móvil, verifica un cálculo con valores de ejemplo y dime qué cambiaste, archivo por archivo.
