Capítulo 15

Incidencias reales y soluciones

Las dudas que efectivamente surgieron en la sesión (A–O), con causa, solución, prompt de reparación y cómo comprobar que quedó resuelto.

Cada causa se marca como confirmada (la transcripción lo muestra) o hipótesis (probable, no demostrada).

A«No encuentro dónde seleccionar la carpeta del proyecto»
Observado

Tras escribir una pregunta, el cuadro de texto quedó abajo y no aparecía el selector (≈ 0:50).

Causa

confirmada El selector aparece en la pantalla inicial de una sesión; al iniciar la conversación ya no se muestra.

Solución

Pulsa + (arriba) para una sesión nueva → opción Project / Choose project → elige la carpeta.

No hagas

No crees la carpeta dentro de la carpeta de instalación de OpenCode.

Comprobar

El nombre del proyecto muestra tu carpeta. Pregunta: «¿en qué carpeta trabajas?».

B«OpenCode sigue trabajando, pero ya veo mi aplicación»
Observado

Dos estudiantes veían su landing en el panel de resultados mientras el agente seguía activo (≈ 2:36, 2:43).

Causa

hipótesis El agente continúa optimizando, corrigiendo o esperando un proceso (servidor local).

Solución

Puedes continuar: abre otra sesión con + o envía el siguiente prompt; el profesor: «él va a dejar en segundo plano lo de la página y dará prioridad a este prompt». Máximo dos mensajes seguidos.

Prompt

¿En qué paso estás? Resume qué falta y si la página ya está completa en la carpeta.

Comprobar

Los archivos existen en la carpeta y la página abre.

C«Me pide pagar alojamiento»
Observado

Un agente pidió pagar hosting; ante la negativa propuso Canva (≈ 2:27).

Causa

confirmada El prompt no indicaba dónde publicar; el agente eligió por su cuenta.

Solución

No pagues. Termina primero el código en local; publica con GitHub Pages (gratuito para repos públicos).

Prompt

No contrates ni sugieras servicios de pago. Termina la página en esta carpeta; la publicaremos después en GitHub Pages.

Comprobar

No se te pidió ningún método de pago.

D«No sé dónde pegar el prompt de GitHub»
Observado

«¿Este último es para OpenCode?», «¿en GitHub?» (2:33, 3:04).

Causa

confirmada Se trabajaba con dos sitios a la vez.

Solución

Todos los prompts van en OpenCode (sesión nueva o la de tu landing). En github.com solo creas la cuenta e inicias sesión.

Comprobar

El agente responde con pasos de instalación o verificación.

E«Mi código no llega al correo»
Observado

Dos estudiantes esperaban el código por email (2:34, 2:58).

Causa

confirmada El código de dispositivo de GitHub CLI se muestra en pantalla (OpenCode o PowerShell), no por correo. (El código de verificación de registro de la cuenta sí llega por correo: son cosas distintas.)

Solución

Busca un código XXXX-XXXX en la respuesta del agente o en la ventana de PowerShell.

Prompt

Muéstrame aquí en el chat el código de un solo uso de GitHub CLI y abre https://github.com/login/device en mi navegador.

Comprobar

La página acepta el código y muestra «Authorize».

F«El código de autorización caducó»
Observado

«Ya caducó porque te da un tiempo» (2:45).

Causa

confirmada Los códigos de dispositivo expiran en minutos.

Solución

Pide uno nuevo y úsalo de inmediato (P10 o su versión mejorada).

Prompt

El código caducó. Cancela el intento anterior, genera un código nuevo, muéstramelo y abre la página de dispositivo. Espera a que te diga "listo".

No hagas

No reutilices un código viejo ni uses un código que te envíe otra persona (GitHub lo advierte: «Never use a code sent by someone else»).

G«Me abrió una ventana de PowerShell»
Observado

Ventana «Windows PowerShell 5.1 · Autorización de GitHub CLI» con cursor parpadeando (2:55).

Causa

confirmada El prompt P11 pidió abrir una terminal visible para el login.

Solución

No la cierres. Lee el código y la URL que muestra; abre la URL en el navegador (copiar con clic derecho/Ctrl+C) y sigue el flujo del capítulo 13.8. Si pregunta algo con opciones, se elige con flechas y Enter.

Comprobar

La ventana muestra «Logged in as…» o se cierra tras autorizar.

H«Me aparece una solicitud de permisos de un editor desconocido»
Observado

Ventana para «hacer cambios en tu equipo» con un nombre de persona desconocido (2:51). La estudiante rechazó.

Causa

no determinable Con la evidencia disponible no se puede saber qué programa era.

Solución

Rechazar fue correcto. Pregunta al agente qué intentó ejecutar y desde qué ruta; reinstala desde la fuente oficial (winget o cli.github.com).

No hagas

No autorices ventanas cuyo editor no reconozcas. Ver 13.9.

J«No sé si ya se conectó mi cuenta de GitHub»
Causa

confirmada No había una verificación objetiva al final.

Comprobar

K«Ya se publicó la página, pero el agente sigue trabajando»
Observado

Enlace visible, agente «detectando un fallo real» (3:11).

Causa

confirmada Estaba corrigiendo un error del código tras la primera publicación.

Solución

Déjalo terminar; al acabar volverá a publicar. Si necesitas cerrar, puedes interrumpirlo («nunca hay problema de interrumpirlo») y retomarlo otro día.

Comprobar

Recarga el enlace (Ctrl+F5) y verifica los cambios.

L«Se terminó mi límite gratuito»
Observado

Una estudiante alcanzó el límite (3:12).

Causa

confirmada Los modelos gratuitos tienen cuotas. El profesor indicó que «se restablece cada ciertas horas» verificar periodo exacto.

Solución

Espera el restablecimiento o cambia a otro modelo gratuito vigente. Tu trabajo está en la carpeta: no se pierde. Se hará repaso en la siguiente clase.

No hagas

No conectes una API de pago con prisa y sin límite de gasto.

Conéctate a mi repositorio de GitHub "dentea", revisa el proyecto y dime qué contiene antes de hacer cambios.

N«¿Puedo conectar dos agentes a la misma carpeta?»
Respuesta

O«¿Cómo continúo otro día sin perder el proyecto?»
Respuesta

Tu trabajo vive en la carpeta (y en el repositorio si ya lo subiste). Abre OpenCode → elige la misma carpeta → sesión nueva. Si se borró la conversación, «hacer un nuevo chat y ahí mismo meter el prompt».

Prompt

Lee esta carpeta y el archivo NOTAS_AGENTES.md (si existe). Resume en qué estado quedó el proyecto y qué faltaba. No modifiques nada todavía.

Comprobar

El agente describe correctamente tu proyecto.
